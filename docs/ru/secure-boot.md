## Как это работает

Bootimus поставляет встроенный набор загрузчиков `secureboot-official`. Он содержит только официально подписанные релизные бинарники, поэтому каждое звено загрузочной цепочки проверяется по ключам, которым стоковая прошивка уже доверяет — без регистрации сертификатов и без изменений прошивки на клиентах:

```
Firmware (Secure Boot on, stock Microsoft keys)
  → ipxe-shimx64.efi     Microsoft-signed shim from the iPXE release
    → ipxe.efi           signed by the iPXE project's Secure Boot CA,
                         which the shim carries as its vendor certificate
      → autoexec.ipxe    fetched over TFTP; Bootimus generates it per client
        → boot menu      as normal
```

Когда вы загружаете извлечённый образ, сгенерированный пункт меню загружает kernel и initrd, а затем по цепочке загружает **собственный подписанный Microsoft shim дистрибутива** из извлечённого ISO командой iPXE `shim`. Этот shim проверяет подпись kernel дистрибутива, замыкая цепочку:

```ipxe
kernel http://server:8080/boot/ubuntu-26.04/vmlinuz ...
initrd http://server:8080/boot/ubuntu-26.04/initrd
iseq ${platform} efi && shim http://server:8080/boot/ubuntu-26.04/iso/EFI/boot/bootx64.efi ||
boot
```

Bootimus обнаруживает shim автоматически во время извлечения ISO. Страж `iseq … ||` превращает строку в no-op на BIOS-клиентах и на сборках iPXE без команды `shim`, а iPXE вызывает загруженный shim только тогда, когда Secure Boot действительно применяется — машины с выключенным Secure Boot загружаются ровно как раньше.

## Включение поддержки Secure Boot

1. Откройте **Bootloaders** в админ-UI и выберите **`secureboot-official`** как активный набор (или задайте его для конкретного клиента в форме редактирования клиента).
2. Если вы используете встроенный proxyDHCP — на этом всё: он автоматически анонсирует `ipxe-shimx64.efi` UEFI-клиентам.
3. Если у вас внешний DHCP-сервер, смените в нём имя UEFI-bootfile на `ipxe-shimx64.efi` (и `ipxe-shimaa64.efi` для ARM64-клиентов). См. [руководство по DHCP](dhcp.md).

Официальные бинарники iPXE не содержат встроенного скрипта Bootimus; они полагаются на то, что iPXE ≥ 2.0 скачивает по TFTP `autoexec.ipxe`, который Bootimus раздаёт. Держите UDP-порт 69 доступным для клиентов.

## Загрузка образов

Для клиентов с Secure Boot используйте **извлечённую (kernel/initrd) загрузку** ваших образов — загрузите ISO и нажмите **Extract** в списке образов. Во время извлечения Bootimus записывает shim `EFI/BOOT/BOOTX64.EFI` (или `BOOTAA64.EFI`) из ISO и автоматически подключает его к меню.

Образам, извлечённым до появления поддержки Secure Boot, нужно повторное извлечение, чтобы подхватить свой shim: удалите boot-папку образа и извлеките заново.

Установка Windows загружается через официальный подписанный Microsoft `wimboot`, который входит в набор `secureboot-official`; всё, что wimboot затем загружает из `boot.wim`, подписано Microsoft.

## Что работает, а что нет

| Сценарий | Под Secure Boot |
|----------|------------------|
| Извлечённые Linux ISO дистрибутивов, поддерживающих Secure Boot (Ubuntu, Debian, Fedora, openSUSE, Rocky, Alma, …) | ✅ Работает |
| Установщик Windows (wimboot) | ✅ Работает |
| Дистрибутивы, не поддерживающие Secure Boot на собственных носителях (Arch, Alpine, Void, …) | ❌ Их kernel не подписаны — так же, как при загрузке с их USB-флешки. Выключите для них Secure Boot. |
| Загрузка `sanboot` (ISO целиком) | ❌ Используйте вместо неё извлечённую загрузку |
| Методы загрузки NBD / NFS | ❌ Они загружают собственный неподписанный kernel Bootimus — см. [ниже](#продвинутое-самоподписанные-загрузчики-для-nbdnfs) |
| Tool-образы (ShredOS, memtest, …) | ❌ Неподписанные kernel |

## Продвинутое: самоподписанные загрузчики для NBD/NFS

Методы загрузки NBD и NFS загружают собственный kernel загрузочного окружения Bootimus, который ни один публичный CA не подпишет. Если они нужны вам под Secure Boot, соберите самоподписанный набор и один раз зарегистрируйте свой сертификат на каждом клиенте:

```bash
scripts/generate-signing-key.sh
BOOTIMUS_SIGNING_KEY=… BOOTIMUS_SIGNING_CERT=… scripts/build-secureboot-set.sh
```

Скопируйте результат в `<data>/bootloaders/secureboot/`, выберите его в UI, затем зарегистрируйте сертификат на каждом клиенте командой `mokutil --import bootimus-signing.crt` (или через управление ключами в прошивке). Для большинства развёртываний проще просто выключить Secure Boot на затронутых машинах.

## Диагностика

- **Заставка «Security Violation» от прошивки до загрузки iPXE** — клиент не скачивает `ipxe-shimx64.efi`. Проверьте имя bootfile в DHCP и то, что набор `secureboot-official` активен.
- **iPXE загружается, но меню не появляется** — официальным бинарникам нужен `autoexec.ipxe` по TFTP. Проверьте UDP 69 между клиентом и сервером.
- **Одна строка «Security Violation» в логе iPXE при загрузке образа** — ожидаемо и безвредно; это iPXE пробует shim-образ, а не сбой.
- **Клавиши меню не отвечают на некотором железе** — у iPXE v2.0.0 известная регрессия клавиатуры в интерактивных меню на отдельных машинах. В качестве обходного пути задайте образ по умолчанию или используйте выбор next-boot, либо переключите этот клиент на набор `default`, если ему не нужен Secure Boot.
- **Kernel отказывается загружаться под Secure Boot** — вероятно, образ был извлечён до появления поддержки shim (извлеките его заново), или дистрибутив вообще не поддерживает Secure Boot.
