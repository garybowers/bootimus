# Сетевая загрузка Raspberry Pi

Загружайте по сети платы Raspberry Pi семейств 3 и 4 без SD-карты. Bootimus содержит всё, что запрашивает прошивка Pi, и передаёт плату прямо в стандартное загрузочное меню UEFI/iPXE.

## Поддерживаемые платы

| Плата | Статус |
|-------|--------|
| Pi 4B, Pi 400, CM4 | ✅ Поддерживается |
| Pi 3B, 3B+, CM3 | ✅ Поддерживается |
| Pi 5 | ❌ Пока нет зрелого порта UEFI (EDK2) |
| Pi 2 и старше, Zero | ❌ Нет прошивки с поддержкой сетевой загрузки |

## Как это работает

Boot ROM/EEPROM Pi скачивает свою прошивку по TFTP, и Bootimus раздаёт всю цепочку из встроенных ресурсов — ничего не нужно раскладывать и прошивать:

```
Pi EEPROM/bootcode netboot (no SD card)
  → TFTP: bootcode.bin / start4.elf + fixup + config.txt
    → config.txt [pi3]/[pi4] filters pick the right UEFI build
      → RPI_EFI_3.fd or RPI_EFI_4.fd (Tianocore EDK2)
        → UEFI PXE → ipxe-arm64.efi → Bootimus boot menu
```

Начиная с меню, Pi — просто ещё один ARM64 UEFI-клиент: извлечённые образы, назначение образов по клиентам, автоустановка — всё работает так же, как на x86.

Прошивка сначала запрашивает файлы с префиксом пути `<8-hex-serial>/`; Bootimus срезает его автоматически, поэтому целый парк плат загружается из одного общего набора файлов без настройки каждой платы.

## Однократная подготовка платы

Единственное, чего Bootimus не может сделать по сети — заставить Pi *попробовать* сетевую загрузку: это политика прошивки, хранящаяся на самой плате:

- **Pi 4 / 400 / CM4**: один раз задайте порядок загрузки в EEPROM, например через `raspi-config` (Advanced Options → Boot Order → Network Boot) или `BOOT_ORDER=0xf12` через `rpi-eeprom-config`. Новые EEPROM автоматически переходят к сетевой загрузке, когда SD-карта отсутствует.
- **Pi 3B+**: поддержка сетевой загрузки встроена в boot ROM — настраивать нечего; просто загрузитесь без SD-карты.
- **Pi 3B / CM3**: один раз загрузитесь с SD-карты с `program_usb_boot_mode=1` в `config.txt`, чтобы установить (необратимый) OTP-бит загрузки.

## Настройка DHCP

Самый простой путь — встроенный proxyDHCP Bootimus (`--proxy-dhcp`): он распознаёт MAC-адреса Raspberry Pi и отвечает прошивке требуемой ей vendor-опцией `Raspberry Pi Boot`, а затем отдаёт стадии UEFI её bootfile `ipxe-arm64.efi` — при этом ваш существующий DHCP-сервер продолжает раздавать IP без изменений.

Если же используется внешний DHCP-сервер, нужно покрыть обе стадии:

1. **Стадии прошивки** нужен `next-server` (опция 66), указывающий на Bootimus, *и* vendor-опция 43 со строкой `Raspberry Pi Boot`.
2. **Стадии UEFI** нужен bootfile `ipxe-arm64.efi` для архитектуры клиента 11 (UEFI ARM64).

Многие DHCP-GUI (в том числе OPNsense/pfSense) не умеют выражать bootfile по архитектурам или vendor-опцию Pi — в таких сетях запустите proxyDHCP параллельно. См. [руководство по DHCP](dhcp.md).

## Переопределения для конкретной машины

Чтобы дать конкретной плате другие файлы прошивки или собственный `config.txt`, положите файлы в директорию данных под серийным номером платы:

```
<data>/raspberrypi/<serial>/config.txt      # this Pi only
<data>/raspberrypi/config.txt               # all Pis, overrides embedded copy
```

Всё, что не переопределено, берётся из встроенных ресурсов. Серийный номер — это 8-значное шестнадцатеричное значение из `cat /proc/cpuinfo` на самом Pi; оно появляется в TFTP-логах Bootimus при первой попытке платы загрузиться по сети.

## Ограничения

- **Только проводной Ethernet** — прошивка Pi не умеет загружаться по сети через WiFi.
- **Настройки UEFI не сохраняются.** У загруженной по сети прошивки нет записываемого хранилища переменных, поэтому она всегда стартует с дефолтами pftf — включая дефолтное ограничение RAM в 3 ГБ на Pi 4. Если вашей ОС нужна вся память, соберите `RPI_EFI.fd` с выключенным ограничением и положите его как переопределение.
- **Pi 5 не поддерживается**, пока его порт EDK2 не созреет; то же касается любой платы без UEFI-прошивки.
- Ресурсы обновляются скриптом `scripts/build-raspberrypi-assets.sh`, который фиксирует версии и проверяет по контрольным суммам релизы UEFI от [pftf](https://github.com/pftf/RPi4). Входящие в них загрузочные блобы Broadcom лицензированы только для использования с устройствами Raspberry Pi (рядом поставляется `LICENCE.broadcom.txt`).
